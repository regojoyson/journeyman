Framework setup

Jira · BMAD · Project Hub · Journeyman — how the four wire together, how to set it up, and the reference docs.

The complete picture

  1. 1Jira status change fires a webhook → Journeyman picks the phase.
  2. 2Sandbox clones the Hub — context and bmad-core.
  3. 3It also clones the story's code repos (from registry.yaml).
  4. 4Agent reads the BMAD persona + context, does the work; pauses for the human gate.
  5. 5Writes artifacts back to the Hub and code to the repos — one GitLab MR each (via the GitLab MCP).
  6. 6Sync mirrors content to Jira and advances the status → next phase.

How to set it up

1
Create the Project Hub repo git
New repo with the folder layout (product/ · technical/ · epics/ · repos/ · process/). Add CONVENTIONS.md.
2
Install BMAD into the Hub bmad
Run npx bmad-method install so bmad-core/ (agents, tasks, templates, checklists) lives inside the Hub, versioned with the project.
3
Configure Jira jira
Build the Story workflow statuses and a webhook on status-change → Journeyman. Add pointer fields — Hub Path, Epic, Repos, MR Links — so agents/devs resolve context fast; the Jira key is the unique id (branch / MR / commit / story jiraKey). Epics stay in the Hub (no Jira epics).
4
Fill repos/registry.yaml hub
List every code repo (url, purpose, tech, owners). Stories reference these short names.
5
Define process/workflow.yaml hub
Map each status → which bmad-core agent runs + the gate (none / role / on-flag). This is the trigger contract.
6
Wire Journeyman journeyman
One custom-ai step per phase whose prompt = "act as bmad-core/agents/<name>.md for {{storyPath}}". Add the Hub to the clone step. Triggers from the Jira webhook. Pauses at gates (built-in).
7
Build the two new pieces new code
(a) the Hub↔Jira sync (create issues from story docs, write jiraKey back, echo status); (b) the Zone-1 trigger for epic phases (fires on a Hub MR merge, since there's no Jira issue yet).
8
Dry-run one epic end to end test
Discovery → Design → Grooming in the Hub → mirror a story → walk it to DONE. Watch the gates, PRs, and sync before rollout.

Sync rules — no drift

DirectionCanonicalWhat flows
CONTENT → Hub to JiraHubtitle, description, links create/update the issue
STATUS ← Jira to HubJirastatus echoed read-only into the doc's frontmatter

Two one-way flows on different fields → they never conflict. Story id is the anchor; jiraKey written back once.
