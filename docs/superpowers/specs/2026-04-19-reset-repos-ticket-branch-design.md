# Ticket-aware `resetRepos` — Design

## Summary

`resetRepos` becomes a combined "sync to origin + create feature branch" operation. It always creates a fresh feature branch after hard-resetting the base branch to origin. The branch name is generated by Claude — either from ticket details (when provided) or as an animal-themed fallback. No push, no commit.

## Motivation

Today, `resetRepos` only hard-resets local repos to match `origin/<branch>`. Every caller that wants to start work on a ticket then has to run a second step to create the feature branch. Bundling the two removes that seam: one call gives you a clean base + a ready-to-use feature branch.

## Behavior change (breaking)

- Old: `resetRepos` left HEAD on the base branch.
- New: `resetRepos` always leaves HEAD on a newly-created feature branch. The reset-only use case is dropped — if a caller really wants reset-only, they can ignore `newBranch` and `git checkout` back, but that is not a supported flow.

## Input

```ts
// packages/core/src/types/git.types.ts
export type ResetReposOptions = SessionOptions & {
  repos: string | string[] | ResetEntry | ResetEntry[];
  branch?: string;                          // base branch to reset to (default "main")
  ticket?: { id: string; title: string };   // optional — drives branch name
  signal?: AbortSignal;
};
```

One ticket per call applies to every repo in the batch. `ResetEntry` is unchanged — it still holds `{ dirPath, branch }` where `branch` is the base branch.

## Branch naming

Claude generates **one** branch name per call, applied identically to every repo in the batch.

- With ticket: `{id-lowercased}/{2-4-word-slug-from-title}_{unix-timestamp-seconds}`
  - Example: ticket `EV-12345` titled "Fix header alignment bug on checkout page" → `ev-12345/fix-header-alignment_1713542400`
- Without ticket: `{animal-themed-2-3-words}_{unix-timestamp-seconds}`
  - Example: `curious-otter-sprint_1713542400`

Rules encoded in the prompt:
- Lowercase ASCII only, words separated by `-`.
- Slug words: 2–4 content words from the title (strip stopwords like "the", "a", "on", "for").
- Timestamp: Unix seconds at generation time, suffixed with `_` for uniqueness.
- Never reuse a pre-existing branch name.

## Per-repo steps (Claude-driven bash)

For each repo, in order:

1. `git -C <dirPath> fetch origin`
2. `git -C <dirPath> stash --include-untracked` — discard local changes so checkout is never blocked
3. `git -C <dirPath> checkout <baseBranch>`
4. `git -C <dirPath> pull origin <baseBranch>` — explicit pull as requested
5. `git -C <dirPath> reset --hard origin/<baseBranch>`
6. `git -C <dirPath> clean -fd` — remove untracked files/dirs
7. `git -C <dirPath> checkout -b <newBranch>`

No push, no commit. Failures are captured per repo and reported in the result.

## Output

```ts
export type ResetResult = {
  folderName: string;
  dirPath: string;
  baseBranch: string;    // the branch we reset from (was previously named `branch`)
  newBranch: string;     // the feature branch just created
  success: boolean;
  error?: string;
};

export type ResetReposResult = SessionResult & {
  repos: ResetResult[];
  newBranch: string;     // same across all repos — convenience for the caller
  error?: string;
};
```

Rename note: the old `ResetResult.branch` becomes `baseBranch`. This is a breaking change to the result shape, acceptable given the overall behavior change.

## JSON schema (for `query()` output)

Top-level schema gains:
- `newBranch: string` (required)
- Each `repos[]` item: `baseBranch` (required), `newBranch` (required).

## Prompt outline

```
Step 1: Generate one branch name following rules below.
  - If ticket provided: "{id-lower}/{2-4-word-slug}_{unix-seconds}"
  - Else: "{animal-themed}_{unix-seconds}"
  - Use this exact same name for every repo.

Step 2: For each repo, run the 7-step sequence using <baseBranch> = entry.branch
  and <newBranch> = the generated name.

Step 3: Return JSON with top-level newBranch + per-repo results.
```

## Files touched

- `packages/core/src/types/git.types.ts` — update `ResetReposOptions`, `ResetResult`, `ResetReposResult`.
- `packages/coding-cli/src/providers/claude/operations/reset-repos.ts` — new prompt, updated `OUTPUT_SCHEMA`, wire `ticket` through, update inline example at the bottom of the file.

No other package or call site needs changes because no caller is consuming `ResetResult.branch` in the repo (to be verified during implementation; if any do, they update to `baseBranch`).

## Out of scope

- Pushing the new branch to origin.
- Creating PR/MR.
- Any commit activity.
- Per-repo ticket overrides — one ticket per call.
