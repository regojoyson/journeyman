# Rename `api-http` → `api-app` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rename the `api-http` package, deployed service, and launcher tokens to `api-app`, so the service is named by its role (the application-facing API) instead of its transport.

**Architecture:** `api-http` is one of three processes run from the `@journeyman/api-server` image. The rename touches three rings — (1) the package `@journeyman/api-http`, (2) the deployed service/host name `api-http`, (3) the launcher tokens inside `api-server` (`cli-start-http`, `server-http`, `start:http`, bin, `buildHttpServer`). The `api-server` image name, ports (`4000`), `http://` URL schemes, and `WEBHOOKS_PORT`/`CONTROL_PLANE_PORT` are **out of scope** and must not change.

**Tech Stack:** npm workspaces monorepo, TypeScript, Fastify, Docker Compose, Kubernetes (kustomize), nginx.

**Execution constraints for this plan:**
- **No `git commit`** — do not commit at any step (not even the final one).
- **Typecheck only at the end** — a single `npm run check` (typecheck + import boundaries) as the last task. No per-task typechecks.
- **Work on `master`** — do not create a branch or worktree.
- Use `git mv` for all file/dir moves to preserve history.
